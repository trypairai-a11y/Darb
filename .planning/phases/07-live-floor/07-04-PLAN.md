<objective>
Wave 4 — Polish + hardening. The map is functionally complete after Wave 3; Wave 4 closes the visibility gaps and ensures the SSE pipeline survives Vercel function lifecycle.

Six deliverables:

1. **Flight-mode marker treatment (Pitfall 5 visual)** — currently a STALE marker is red regardless of whether the driver is online (app open, GPS broken / flight mode) or offline (app force-closed). Wave 4 distinguishes the two visually:
   - `online=true && stale` → red dot with `animate-pulse` class + Popup tooltip reads "GPS not updating (flight mode?)"
   - `online=false && stale` → red dot WITHOUT pulse + Popup tooltip reads "Offline"
   The `classifyCourier` enum from Wave 2 stays as-is (single STALE bucket); the differentiation is purely visual inside `<CourierMarker/>`.

2. **Connection status indicator** — the header currently shows a text-only "Connected / Reconnecting…" line. Wave 4 promotes this to a small badge component with a coloured dot (emerald-500 when connected, amber-500 when not) for at-a-glance status. Replaces the existing text in `<LiveFloorPage/>`'s header.

3. **Empty state** — when a fresh tenant (or one with no drivers yet) loads `/floor`, Wave 3 shows the map alone with no markers — confusing. Wave 4 adds `<EmptyFloorState/>` that renders centered when `couriers.length === 0 && !snapshotLoading` with a friendly copy and a link to the onboarding wizard.

4. **SSE reconnect proof** — Wave 0's `useFloorRealtime.test.tsx` checked the SSE compose; Wave 4 adds a dedicated integration test `sseReconnect.test.tsx` that simulates a disconnect → backoff → reconnect cycle and asserts the next received `gps_point` updates the marker correctly. Closes the verification gap from Pitfall 4.

   **W4 — cross-test pollution guard:** the test captures `const realEs = globalThis.EventSource` AT MODULE LOAD (before any `beforeEach` runs). The `afterAll` block restores `globalThis.EventSource = realEs` — to the originally-captured reference, not the platform's native global. This prevents leakage if Vitest's parallel-test runner mounts a different `EventSource` polyfill in another test file (e.g. Phase 4 chat tests), and ensures the cleanup is idempotent across test ordering.

5. **Vercel function maxDuration** — `backend/vercel.json` does not currently set `maxDuration` per-function. Wave 4 adds the 300s setting for the `api/index.ts` entry (which mounts the Express app including `/api/events`). On Vercel Pro with Fluid Compute, this raises the default from 15s to 300s — well-known fix from Phase 4's SSE research + Pitfall 4.

6. **Phase 10 deferred-items.md entry (W3)** — append a deferred-items entry pointing to the canonical cross-platform Order-rejection signal path. This is the documentation half of W3 (the UI half — the tooltip note — landed in Plan 03's FloorPillCounters). Path: `OrderEvent.action='REJECT'` aggregate, scoped to the tenant, with a per-driver count threshold of >=3 in the last 24h.

After Wave 4, the Phase 7 surface ships. Phase 8 picks up the action-tool surface; Phase 9 wires real WhatsApp delivery into the existing Ping flow.

// Phase 7 Wave 4 — SSE auto-reconnect end-to-end.
// Mocks EventSource directly + uses real useFloorRealtime to verify the
// reconnect cycle propagates `connected` state changes and resumes gps_point delivery.
//
// W4 — cross-test pollution risk:
//   Vitest may share globalThis state across test files in a single worker.
//   If this test file SWAPS globalThis.EventSource and forgets to restore,
//   any later test that imports useSSE (e.g. Phase 4 chat reconnect tests)
//   will receive a stale FakeEventSource class.
//   Mitigation: capture `globalThis.EventSource` at MODULE LOAD (top-level
//   const, before any `vi.mock` or `beforeEach`) and restore to THAT value
//   in `afterAll`. This pins the cleanup target to whatever was installed
//   when this module first evaluated — which may be the native browser
//   EventSource OR a polyfill from frontend/src/__tests__/setup.tsx.
//   We do NOT assume the native constant is the right restore target.
import { describe, test, expect, vi, beforeEach, afterAll } from "vitest";
import { render, waitFor, act } from "@testing-library/react";
import { QueryClient, QueryClientProvider } from "@tanstack/react-query";

// W4: capture at MODULE LOAD — before any test hook runs.
// This is the reference we restore to in afterAll.
const realEs = (globalThis as any).EventSource;

// Fake EventSource that we control externally
class FakeEventSource {
  static instances: FakeEventSource[] = [];
  url: string;
  readyState = 0;
  onopen: ((this: EventSource, ev: Event) => any) | null = null;
  onmessage: ((this: EventSource, ev: MessageEvent) => any) | null = null;
  onerror: ((this: EventSource, ev: Event) => any) | null = null;
  withCredentials = false;
  constructor(url: string) {
    this.url = url;
    FakeEventSource.instances.push(this);
  }
  close() { this.readyState = 2; }
  addEventListener() {}
  removeEventListener() {}
  dispatchEvent() { return true; }
}

vi.mock("@/lib/api", () => ({
  default: {
    get: vi.fn().mockResolvedValue({ data: { couriers: [], scheduledNotOnline: 0, gpsStale: 0, orderRejection: 0 } }),
  },
  getAccessToken: () => "test-token",
}));

// Mount useFloorRealtime via a test harness component
import { useFloorRealtime } from "@/hooks/useFloorRealtime";
function Harness({ onState }: { onState: (s: { connected: boolean; courierCount: number }) => void }) {
  const { couriers, connected } = useFloorRealtime();
  onState({ connected, courierCount: couriers.length });
  return null;
}

describe("Phase 7 Wave 4 — SSE reconnect cycle", () => {
  beforeEach(() => {
    (globalThis as any).EventSource = FakeEventSource;
    FakeEventSource.instances.length = 0;
  });

  // W4: restore to the captured reference (NOT to the native constant).
  // Other tests in this Vitest session may rely on the polyfill that was
  // installed by setup.tsx; restoring to that exact reference keeps them safe.

    vi.useRealTimers();

  test("disconnect → connected goes false → backoff → reconnect → connected goes true", async () => {
    vi.useFakeTimers();

      <QueryClientProvider client={qc}>
        <Harness onState={(s) => states.push(s)} />
      </QueryClientProvider>,

      await Promise.resolve();
    });

    act(() => { first.onopen?.(new Event("open")); });
    await waitFor(() => expect(states.at(-1)?.connected).toBe(true));
    act(() => { first.onerror?.(new Event("error")); });
