## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Tenant.partnerApiSecrets (Json column) | per-tenant credentials at rest; envelope-encrypted with PORTAL_CRED_KEY |
| BullMQ job payload → Redis | job carries ONLY { tenantId, platform }; credentials fetched inside worker |
| Partner-API HTTP call → Keeta servers | TLS-only (V9); Bearer token in Authorization header |
| Admin route → encryptCred → DB | apiKey enters server process once, gets encrypted, never logged or echoed |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

Decrypted key never serialized back to Redis. (RESEARCH §Security row 3) |
| T-11-W3-02 | Information Disclosure | Decrypted Keeta API key logged in error message | mitigate | KeetaAdapter wraps fetch in try/catch; error message sanitization strips base64-looking token substrings before logging or re-throwing |
| T-11-W3-03 | Information Disclosure | Admin POST /api/admin/partnerApi/credentials echoes apiKey back in response | mitigate | Response schema explicit: { ok, tenantId, platform, updatedAt } — apiKey NOT in response; AgentAction audit row originalProposal sanitized to { tenantId, platform, baseUrl } only |
| T-11-W3-04 | Tampering | Caller-supplied baseUrl="http://attacker.com/..." → credentials sent over cleartext | mitigate | validateHttpsUrl helper throws on non-https baseUrls before storage AND before fetch. Both points enforced (V9) |
| T-11-W3-05 | Repudiation | Partner-API webhook replay (Deliveroo) | mitigate (future) | Deliveroo skeleton ships NotAvailable; Phase 12 webhook receiver verifies HMAC + stores eventId in IngestRun.runIdempotencyKey (V13 + Phase 6 pattern) |
